## Reading the results

These notes were written by hand from the table above. Re-running the script replaces the table but
not this section.

* **Same output, same codec.** For every format, archive sizes are within 1–4% of the reference tool,
  because the same codecs (zlib, liblzma, zstd, 7-Zip's LZMA2) do the work. Universal Archiver's
  tar.gz/tar.zst outputs are slightly *smaller* on source code. The likely reason is that
  directory entries are added in sorted name order, not directory order, so similar files sit
  together. This was not isolated experimentally.
* **Large inputs: on par.** On the 40–60 MB datasets, ZIP, tar.gz, tar.xz and 7z compression times are
  within ±10% of Info-ZIP, GNU tar + gzip/xz and 7-Zip; Universal Archiver is faster in about half of
  the rows. Extraction times are equal within noise.
* **Fixed start-up cost.** This run used a build that probed the helper tools on every launch
  (≈0.2 s). That dominates the short rows (tar.zst in 0.3 s vs 0.1 s; the 20k-small-files rows).
  Helper probes are now cached (`ProbeCache`); measured afterwards on the same machine, a complete
  `archiver compress` of one small file takes 0.03–0.06 s. The table has **not** been regenerated
  with that build.
* **Many small files.** Compression is 2–7× slower than the C tools on the 10,000-file dataset
  (0.5 s vs 0.1–0.2 s). Most of that is start-up cost plus per-file work in the safe walker:
  `lstat`, loop detection and filter evaluation. Our ZIP is 10% larger there because each entry
  carries Unix UID/GID and extended-timestamp extra fields (30 bytes more per entry than Info-ZIP's
  defaults). Those fields preserve ownership and times.
* **Memory.** Baseline resident memory is ≈31 MB (Swift runtime and Foundation) vs 2–7 MB for the C
  tools. With multithreaded xz and zstd, peak memory is 10–40% above the reference because of
  larger in-flight buffers. Memory does not grow with input size: see
  `StressTests.testStreamingKeepsMemoryBounded`.
* **Single run.** Each measurement is one run on a shared 4-vCPU VM; differences below ~10% are
  within noise. One example: extracting the two 10,000-file 7z archives, both with our tool, took
  5.1 s and 2.3 s.
* **Not measured:** Apple Silicon, P/E-core scheduling, Low Power Mode and thermal behaviour, Apple
  Archive (LZFSE), and DMG/ISO creation.
